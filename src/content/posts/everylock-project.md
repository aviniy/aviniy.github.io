## 1. 연구 목적

로그인 실패 횟수 누적에 따른 계정 잠금 정책이 정상 사용자 접근성에 미칠 수 있는 영향을 살펴보고, 인증 오류 메시지의 차이가 계정 존재 여부를 노출할 가능성이 있는지 검토한다. 실서비스 관찰과 별개로 로컬 실습 환경에서 EveryLock 시뮬레이터를 제작했다.

## 2. 실서비스에서 관찰한 사실

### 관찰 A — 존재하지 않는 학번에 대한 응답

화면에는 “사용자 아이디 또는 비밀번호가 일치하지 않습니다.”라는 문구가 표시됐고 실패 횟수는 보이지 않았다.

### 관찰 B — 실제 존재하는 학번에 대한 응답

“사용자 아이디 또는 비밀번호가 일치하지 않습니다. 1회 실패됨.”처럼 같은 기본 오류 메시지 뒤에 실패 횟수가 표시됐다.

### 관찰 C — 실패 횟수 초과 응답

반복 실패 후 비밀번호 오류 횟수를 초과했다는 경고창과 관리자 문의 안내가 표시됐다. 실제 정상 비밀번호를 사용한 로그인까지 차단되는지는 확인하지 못했다.

### 관찰 D — 별도의 영문 오류 메시지

과거 관찰에서는 `It's an invalid username.`이라는 메시지도 표시됐다. 위 한국어 오류와 다른 인증 흐름 또는 상태에서 발생했을 가능성이 있으므로 동일 조건에서의 일관된 동작으로 단정하지 않는다.

### 관찰 E — 환경 변경 후 경고

IP·브라우저를 변경한 뒤에도 오류 횟수 초과 경고가 나타났다는 관찰이 있다. 변경 후 최초 시도부터 즉시 나타났는지, 계정 단위 잠금인지 등은 확인되지 않았다.

## 3. 보안상 의미 및 확신 수준

### 후보 1 — 계정 존재 여부 노출 (Username Enumeration)

**관찰 근거:** 실제 학번에서는 ‘1회 실패됨.’이 붙었고, 존재하지 않는 학번에서는 붙지 않았다.

**추정 위험:** 같은 조건에서 이 차이가 반복된다면 응답 차이를 이용해 계정 존재 여부를 추측할 수 있다.

**관련 분류:** CWE-203 (Observable Discrepancy).

**판정:** 가능성 있음. 서버 구현과 반복 일관성은 미확인.

### 후보 2 — 계정 잠금 악용에 따른 가용성 저하 (Account Lockout DoS)

**관찰 근거:** 인증 실패 횟수가 표시되고 임계치 초과 경고가 관찰됐다.

**추정 위험:** 제3자의 실패 시도로 실제 계정이 잠기고 정당한 사용자의 정상 로그인도 막힌다면 가용성 문제가 될 수 있다.

**판정:** 위험 가설. 실제 정당한 사용자의 접근 차단, 잠금 지속시간, 해제 정책은 확인되지 않았다.

## 4. EveryLock 로컬 PoC

Python·Tkinter GUI와 로컬 웹 인증 서버를 이용해 다음 기능을 구현했다.

- 가상 계정 생성
- 로그인 실패 횟수 누적
- 10회 실패 후 잠금
- 잠긴 계정 표시
- 전체 잠금 해제
- 로그 JSON 내보내기

기본 로컬 웹 주소는 `http://127.0.0.1:4173`이다. GUI는 외부 호스트를 거부하고 루프백 주소만 허용하며, CLI 스크립트도 루프백 4173 포트만 허용하도록 구성했다.

이 로컬 시뮬레이션은 설계된 잠금 정책의 동작을 보여줄 뿐, 대학 실서비스의 실제 영향 범위를 입증하지 않는다.

## 5. 확인되지 않은 사항

- 정상 비밀번호로 로그인하려는 사용자가 실제로 차단되는지
- 잠금 기준이 계정·세션·IP 중 무엇에 귀속되는지
- 잠금 지속 시간과 복구 방법
- 오류 메시지 차이가 모든 조건에서 일관적인지
- 실서비스에서 대규모 계정 잠금이 가능한지

## 6. 권고 사항

1. 학교 IT·보안 담당자에게 스크린샷과 관찰 조건을 비공개로 전달한다.
2. 추가 검증이 필요하면 학교가 발급한 승인된 테스트 계정과 범위를 사용한다.
3. 인증 오류 응답을 통일하고 계정 존재 여부가 드러나는 정보 차이를 줄이는 방안을 검토한다.
4. 무차별 로그인 시도 방어와 정상 사용자 접근성을 함께 고려해 계정 잠금, 속도 제한, 이상 징후 탐지, 복구 절차를 설계한다.
5. 로컬 PoC에서 기존 잠금 정책과 개선 정책의 정상 사용자 차단 비율을 비교한다.

## 7. 관찰 자료 해석

원문에는 다음 다섯 단계의 화면 관찰 기록이 포함돼 있다.

1. 미등록 ID로 추정되는 입력: 실패 횟수 미표시
2. 등록 ID로 추정되는 입력: 1회 실패 표시
3. 실패 횟수 누적 관찰: 2회
4. 5회 실패 시 비밀번호 재설정 및 잠금 사전 안내
5. 임계치 초과 및 관리자 문의 경고

이 자료는 계정 존재 여부와 잠금 정책의 실제 구현을 확정하는 증거가 아니라 추가 검토가 필요한 정황 증거로 해석한다.

| 입력·상태 | 화면상 문구 | 해석 |
| --- | --- | --- |
| 미등록 ID 추정 | 실패 횟수 없음 | 계정 존재 여부 노출 가능성 |
| 등록 ID 추정 | 1회·2회·5회 실패 표시 | 계정 단위 상태 누적 가능성 |
| 임계치 초과 | 관리자 문의 안내 | 잠금 정책 존재 가능성 |

> 공개·제보 전에는 학번, 개인정보, 세션·인증 값이 포함되지 않았는지 다시 확인한다.

## 8. 결론

현재까지 **오류 메시지의 차이**와 **인증 실패 횟수에 따른 잠금 경고**가 관찰됐다. 이를 근거로 계정 열거 가능성과 잠금 정책 악용 위험을 제기할 수 있지만, 실서비스에서 취약점이 확정됐거나 대규모 서비스 거부가 재현됐다고 말할 근거는 없다.

EveryLock은 이 위험을 안전하게 설명하기 위한 로컬 시뮬레이션 PoC다.

## 9. CWE 분류 및 판단 근거

아래 CWE는 지금까지 수집한 화면 증거를 해석하기 위한 **후보 분류**다. CWE 번호가 붙었다고 실서비스 취약점이 확정되는 것은 아니다. CVE 번호는 확인되지 않았다.

| CWE | 취약점 유형 | 이번 관찰과의 관계 | 판정 |
| --- | --- | --- | --- |
| **CWE-204** | Observable Response Discrepancy | 미등록 ID 추정 입력에는 실패 횟수 미표시, 등록 ID 추정 입력에는 ‘1회 실패됨.’ 표시 | **가장 직접적인 후보** |
| **CWE-203** | Observable Discrepancy | 오류 메시지 차이를 통해 계정 존재 여부가 드러날 가능성 | **상위 범주의 관련 후보** |
| **CWE-645** | Overly Restrictive Account Lockout Mechanism | 실패 횟수 누적과 임계치 초과 경고가 관찰됨. 정상 사용자 로그인 차단은 미확인 | **위험 가설** |
| CWE-307 | Improper Restriction of Excessive Authentication Attempts | 현재는 오히려 시도 횟수를 제한하는 정황이 있음 | **현재 증거로 해당 주장 불가** |
| CWE-209 | Generation of Error Message Containing Sensitive Information | 내부 경로·스택 트레이스·민감한 내부 정보 노출은 확인되지 않음 | **현재 증거로 해당 주장 불가** |

### CWE-204 / CWE-203 — 인증 오류 응답 차이

**근거:** 기본 오류 문구만 나타난 화면과 동일한 문구 뒤에 ‘1회 실패됨.’이 추가된 화면이 각각 관찰됐다. 이후 2회·5회 실패 표시도 확인됐다. 입력 계정의 존재 여부에 따라 응답이 구분된다면 사용자명 열거 위험이 생길 수 있다.

**한계:** 두 입력의 조건이 완전히 동일했는지, 모든 계정에서 반복되는지 확인되지 않았다. 따라서 계정 열거가 확정되었다고 표현하지 않는다.

**공식 분류:** [MITRE CWE-204](https://cwe.mitre.org/data/definitions/204.html), [MITRE CWE-203](https://cwe.mitre.org/data/definitions/203.html)

### CWE-645 — 계정 잠금에 의한 가용성 저하 가능성

**근거:** 5회 실패 시 재설정·잠금 사전 안내가, 임계치 초과 시 관리자 문의 경고가 기록돼 있다. IP·브라우저 변경 뒤에도 초과 경고가 관찰됐다는 기록이 있다.

**위험 시나리오:** 제3자의 인증 실패만으로 계정 잠금이 유지되고, 그 상태에서 정당한 사용자의 정상 로그인도 차단된다면 계정 가용성 문제가 발생할 수 있다.

**한계:** 정상 비밀번호 로그인 차단, 잠금 지속시간, 복구 수단 및 잠금 적용 단위가 확인되지 않았다. 로컬 EveryLock에서 재현한 잠금은 실서비스 취약점의 증거가 아니다.

**공식 분류:** [MITRE CWE-645](https://cwe.mitre.org/data/definitions/645.html)

### 현재 적용하기 어려운 CWE — 307 / 209

- **CWE-307:** 과도한 인증 시도 제한이 부적절한 유형이다. 현재는 실패 횟수 제한이 존재하는 정황이므로, 제한 우회나 부재가 확인되지 않은 상태에서 붙이기 어렵다. [MITRE CWE-307](https://cwe.mitre.org/data/definitions/307.html)
- **CWE-209:** 오류 메시지에 민감한 정보가 포함되는 유형이다. 현재 화면 증거는 주로 응답의 차이에 관한 것이므로 CWE-204/203이 더 적절하다. [MITRE CWE-209](https://cwe.mitre.org/data/definitions/209.html)

### CVE 상태

**CVE: 미확인 / 미부여 여부도 확인되지 않음.** CWE는 취약점 유형이고 CVE는 특정 제품의 개별 취약점 식별자다. 이번 관찰만으로 임의의 CVE를 적용하거나 신규 CVE 발급 가능성을 단정할 수 없다. [CVE 공식 사이트](https://www.cve.org/)

### 보고서용 한 줄 결론

**주요 후보: CWE-204(및 상위 CWE-203), CWE-645.** 인증 오류 메시지 차이와 실패 횟수 초과 경고는 관찰됐지만, 실제 계정 열거의 일관성 및 정상 사용자 로그인 차단은 미검증이다.

## 10. 공개 범위

원문에 있던 실서비스 계정 잠금 자동화 코드는 제3자의 계정 가용성을 해칠 수 있어 공개 게시글에는 포함하지 않았다. 검증은 승인된 테스트 계정과 로컬 EveryLock 시뮬레이터 범위에서 수행하는 것이 안전하다.
