<header><h1 class="page-title" dir="auto">Level 13 → Level 14</h1><p class="page-description" dir="auto"></p></header><div class="page-body"><h2 id="문제-0" class="" dir="auto">문제:</h2><figure id="3e157476-16b2-80d0-91e5-d44069243277" class="image" data-notion-image="Level%2013%20%E2%86%92%20Level%2014/image.png" dir="ltr"><a href="../../assets/notion/a7208a6f37.png"><img src="../../assets/notion/a7208a6f37.png"></a></figure><p id="3e157476-16b2-8036-b607-d3b7923b7caf" class="" dir="auto">다음 레벨의 비밀번호는 <code>/etc/bandit_pass/bandit14</code>에 저장되어 있으며, bandit14 사용자만 읽을 수 있다. 이번 레벨에서는 다음 레벨의 비밀번호를 직접 얻는 대신, 다음 레벨에 로그인할 때 사용할 수 있는 SSH 개인키를 받게 된다. 이전 Bandit 레벨들에 로그인할 때 사용했던 명령어를 살펴보고, 이번 레벨에서 이 키를 어떻게 사용하는지 알아내라.</p><p id="3e157476-16b2-8083-8d64-ea34e9056ada" class="" dir="auto">
</p><figure id="3e157476-16b2-80e3-b9af-d962a83ca4ae" class="image" data-notion-image="Level%2013%20%E2%86%92%20Level%2014/image%201.png" dir="ltr"><a href="../../assets/notion/4314e1c177.png"><img src="../../assets/notion/4314e1c177.png"></a></figure><p id="3e157476-16b2-8017-aee4-e7612a4c3e2d" class="" dir="auto"><code>ls</code>명령어를 입력하니 HINT 파일과 sshkey.private라는 파일이 있다. 처음에는 <code>ssh -i sshkey.private </code><code><a>bandit14@localhost</a></code><code> -p 2220</code> 명령어를 사용하여 bandit13 서버 내부에서 bandit14 계정으로 ssh 접속을 시도하였지만, bandit 서버에서는 자원 절약을 위해 localhost에서 다시 ssh 서버로 접속하는 것을 차단하고 있었다.</p><p id="3e157476-16b2-803c-bb87-fd620ac7f774" class="" dir="auto">그래서 일단 bandit을 나오고 내 컴퓨터인 윈도우 cmd에서 다음과 같이 입력했다. </p><p id="3e257476-16b2-800e-a768-ef1fd80d20cc" class="" dir="auto"><code>scp -P 2220 </code><code><a>bandit13@bandit.labs.overthewire.org</a></code><code>:sshkey.private bandit14_new.key</code></p><p id="3e257476-16b2-800b-9438-c33f4b6e94f4" class="" dir="auto"><code>scp</code> 명령어는 SSH를 기반으로 로컬과 원격 시스템 사이에서 파일을 복사하는 명령어이다.</p><figure id="3e157476-16b2-80eb-bc69-f3f3b159541e" class="image" data-notion-image="Level%2013%20%E2%86%92%20Level%2014/image%202.png" dir="ltr"><a href="../../assets/notion/08533270c4.png"><img src="../../assets/notion/08533270c4.png"></a></figure><figure id="3e157476-16b2-80ac-9f29-fd35d6f07d9a" class="image" data-notion-image="Level%2013%20%E2%86%92%20Level%2014/image%203.png" dir="ltr"><a href="../../assets/notion/dd53077a35.png"><img src="../../assets/notion/dd53077a35.png"></a></figure><p id="3e157476-16b2-80a2-9b76-edea602a1418" class="" dir="auto">그러면 bandit13 서버의 <code>sshkey.private</code> 파일이 내 Windows에 <code>bandit14_new.key</code>라는 이름으로 복사된다.</p><p id="3e157476-16b2-80ee-af53-f8f1bb067318" class="" dir="auto">
</p><p id="3e157476-16b2-8052-a258-ea94c2af7fbc" class="" dir="auto">그 후 윈도우에서 아래와 같이 두 명령어를 입력했다.</p><figure id="3e157476-16b2-80f2-890f-d5a1c7aa61f2" class="image" data-notion-image="Level%2013%20%E2%86%92%20Level%2014/image%204.png" dir="ltr"><a href="../../assets/notion/907966e3f3.png"><img src="../../assets/notion/907966e3f3.png"></a></figure><p id="3e157476-16b2-806f-8b71-feb2b48134f7" class="" dir="auto"><code>icacls bandit14_new.key /inheritance:r</code>은 윈도우에서 파일/폴더의 접근 권한을 확인하거나 변경하는 명령어이고 여기서 <code>/inheritance:r</code>은 <code>/inheritance</code> = 권한 상속 설정, <code>:r</code>= 상속받은 권한 제거이다. 윈도우에서는 파일을 만들면 보통 상위 폴더의 권한을 물려받는다. 그런데 ssh 개인키는 다른 사용자가 읽을 수 있으면 안 되므로 상속된 권한을 일단 제거 한 것이다.</p><p id="3e157476-16b2-8091-a948-e5a46fa33488" class="" dir="auto">
</p><p id="3e157476-16b2-8000-9420-ebc52d4a5d16" class="" dir="auto">두번째로 <code>icacls bandit14_new.key /grant:r "%USERNAME%:R"</code>은 권한을 다시 부여하는 명령어이다. <code>/grant:r</code> = 기존 명시적 권한을 교체하면서 권한 부여, <code>%USERNAME%</code>현재 로그인한 Windows 사용자 이름, <code>:R</code> = (Read) 읽기 권한.</p><p id="3e157476-16b2-80f4-b1fb-f4c743e2db3a" class="" dir="auto"><br>SSH 개인키는 다른 사용자가 접근할 수 있도록 설정되어 있으면 보안상의 이유로 SSH에서 사용을 거부할 수 있다. 따라서 Windows의 <code>icacls</code> 명령어를 이용하여 상속된 권한을 제거하고 현재 사용자에게만 읽기 권한을 부여하였다.</p><p id="3e157476-16b2-80e1-b7c5-f1b20f341d13" class="" dir="auto">
</p><figure id="3e157476-16b2-80ff-b344-c5eb03ed52ba" class="image" data-notion-image="Level%2013%20%E2%86%92%20Level%2014/image%205.png" dir="ltr"><a href="../../assets/notion/34d951f8ac.png"><img src="../../assets/notion/34d951f8ac.png"></a></figure><p id="211b22f7-4dbc-45ce-a5ce-81936d9c0569" class="" dir="auto">SSH는 비밀번호뿐만 아니라 공개키/개인키를 이용한 인증도 지원한다. 이번 문제에서 제공된 <code>sshkey.private</code>는 bandit14 계정에 로그인할 때 사용할 수 있는 개인키이므로, bandit14의 비밀번호를 알지 못하더라도 이 개인키를 이용하여 인증할 수 있다.</p><p id="3e157476-16b2-8038-bf39-de93c6528dbc" class="" dir="auto">그 후, 평소에 밴딧 들어가는 명령어 앞에 <code>-i bandit14_new.key</code>를 붙인다. <code>-i</code>는 identity file (인증에 사용할 키 파일)을 지정하는 옵션을 의미하고 <code>bandit14_new.key</code>는 아까 우리가 설정한 파일명이다.</p><p id="3e157476-16b2-80ef-8185-d7dff5467d6b" class="" dir="auto">
</p><figure id="3e157476-16b2-80f8-8465-c657964615e7" class="image" data-notion-image="Level%2013%20%E2%86%92%20Level%2014/image%206.png" dir="ltr"><a href="../../assets/notion/5bba495c07.png"><img src="../../assets/notion/5bba495c07.png"></a></figure><p id="3e157476-16b2-802a-93bc-fba601281cb4" class="" dir="auto">그렇게 bandit14 계정으로 접속한 뒤 문제에 적혀 있던 <code>/etc/bandit_pass/bandit14</code> 파일을 <code>cat</code> 명령어로 확인하면 다음 레벨에서 사용할 비밀번호를 얻을 수 있다.</p><p id="3e157476-16b2-80da-8d47-fa68dd9b1cd4" class="" dir="auto">
