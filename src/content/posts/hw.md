### 나는 왜 공부하려 하는가?

요즘 리버싱 문제를 풀면서 포인터 개념과 메모리에 관한 기본 지식이 필요하다 생각했다. (기본 지식이 부족하니까 문제를 풀때 이해를 하지 못하는게 아쉬웠음). 그래서 나는 기초 지식을 보완하고, 개념을 확실하게 잡겠다는 마인드로 이 페이지를 작성하게 되었다.

### 왜 알아야 하는가?

프로그램이 실행되면 변수와 데이터는 메모리에 저장되며, 각각 데이터는 메모리 주소를 통해 접근할 수 있다. **포인터(pointer)**는 이러한 메모리 주소를 저장하고 참조할 수 있도록 하는 개념이다.

리버싱은 프로그램의 내부 동작을 분석하는 과정이니까, 프로그램이 메모리를 어떻게 사용하고 데이터에 어떻게 접근하는지 이해하는 것이 중요하다. 특히 어셈블리어를 분석할 때 레지스터에 저장된 값이 단순한 숫자인지, 특정 메모리 주소를 나타내는지 구분해야 하는 경우가 많다.

또한 운영체제의 메모리 관리, 자료구조의 구현, 시스템 프로그래밍 등 다양한 분야에서 메모리 주소와 포인터에 대한 개념과 지식을 요구한다.

따라서 메모리 주소와 포인터의 개념을 이해하면 프로그램의 데이터 처리 과정과 메모리 접근 방식을 더욱 정확하게 분석할 수 있다.

## CPU의 기본 구조

아니 메모리와 포인터에 관해서 공부하겠다는데, CPU의 기본 구조는 왜 나오는걸까?

사실 메모리와 포인터를 이해하려면 먼저 CPU가 데이터를 어떻게 처리하고 메모리와 상호작용하는지 알아야한다. CPU는 프로그램의 명령어를 실행하는 장치이며, 연산에 필요한 데이터를 메모리에서 가져오거나 처리한 결과를 다시 메모리에 저장할 수 있다.

또한 CPU 내부에는 레지스터(Register)라는 작은 저장 공간이 존재한다. 이곳에는 연산에 필요한 데이터뿐만 아니라 메모리 주소도 저장할 수 있다. 따라서 CPU의 기본 구조와 역할을 이해하면, 메모리에 저장된 데이터가 어떻게 처리되는지, 포인터가 나타나는 메모리 주소가 실제로 어떻게 활용되는지 이해하는데 도움이 된다.



### CPU란 무엇인가?

CPU(Central Processing Unit)는 중앙처리장치로, 프로그램의 명령어를 해석하고 실행하는 컴퓨터의 핵심 장치이다.

CPU는 단순히 수학적인 계산만 수행하는 것이 아니라, 데이터의 이동, 논리 연산, 명령어 실행 흐름 제어 등 다양한 작업을 수행한다. 그럼 CPU의 주요 구성 요소는 다음과 같다.

1. 제어장치(Control Unit, CU): 클럭, 현재 수행할 명령어, 플래그 등의 정보를 바탕으로 제어 신호를 생성하여 CPU 내부의 동작을 제어하는 장치이다.
2. 산술논리연산장치(Arithmetic Logic Unit, ALU): 덧셈, 뺄셈 등의 산술 연산과 AND, OR등의 논리 연산을 수행하는 장치이다.
3. 레지스터(Register): CPU 내부에 존재하는 작고 빠른 저장 공간으로, 명령어 실행에 필요한 데이터와 메모리 주소 등을 일시적으로 저장한다.

이렇게 주요 구성 요소 3가지가 있는데.. 클럭은 뭐고 플래그는 뭐고 제어 신호는 또 뭘까.. 이것도 조사해봤다.

1. 클럭(Clock): 클럭은 CPU 내부의 회로들이 일정한 타이밍에 맞춰 동작하도록 하는 주기적인 전기 신호이다. 쉽게 말하면 CPU의 박자라고 생각하면 되는데, CPU 사양을 보면 `3.0GHz`, `4.0GHz`라는 표현을 본적이 있을거다. 사실 이게 클럭 주파수이고, 예를 들어 `3GHz`는 1초에 30억번의 클럭 주기가 반복된다는 뜻이다.
2. 플래그(Flag): 플래그는 CPU의 연산 결과나 특정 상태를 나타내는 정보이다. 예를 들어..

```
mov rax, 10
sub rax, 10
```

이런 어셈블리어가 있다 해보자. 첫번째 명령어에선 `RAX`에 10을 저장한다. 두번째 명령어에선 `RAX`에서 10을 뺀다. 그래서 `10 - 10 = 0`의 결과가 나오게 된다. 이때 CPU는 결과가 0이라는 사실을 플래그에 기록할 수 있다.

3. 제어 신호(Control Signal): 제어 신호는 CPU 내부의 각 회로에 어떤 동작을 수행해야 하는지 알려주는 전기 신호이다. 이걸 이해할려면 CU와 ALU의 관계를 생각하면 되는데, CU는 어떤 작업을 수행할지 결정하고 필요한 제어 신호를 생성하고, ALU는 제어 신호에 따라 산술,논리 연산을 수행한다.

예를 들어 `add rax, rbx`라는 어셈블리어가 실행된다 해보자. 이 명령어는 `RAX`와 `RBX`의 값을 더해서 `RAX`에 저장하라는 뜻이다. 만약 `RAX`에 10, `RBX`에 20이 저장되어 있다면, CU는 덧셈 연산에 필요한 제어 신호를 생성하고 ALU는 두 값을 더하는 연산을 수행한다.

## 메모리(Memory)란?

음 이제 드디어 메모리를 공부해보자.. 우리는 흔히 메모리를 RAM이라고 생각하는데.. 물론 틀린말은 아니다. 실제로 컴퓨터에서 메모리라고 하면 일반적으로 RAM을 지칭하는 경우가 많다. **하지만** RAM은 메모리의 종류일뿐 메모리 자체가 아니라는 점을 알아야한다.

메모리(Memory)는 컴퓨터에서 데이터와 명령어 등의 정보를 저장하는 장치나 공간을 의미한다. 그리고 그 종류에는 위에서 배운 레지스터(Register)하고 캐시 메모리(Cache Memory), RAM, ROM, 플래시 메모리 등이 있다.



### 메모리의 종류와 특징

- 레지스터(Register) - 레지스터는 CPU 내부에 존재하는 매우 작고 빠른 저장 공간이다. CPU 공부에서 이미 다뤘으니 생략하도록 하겠다.
- 캐시 메모리(Cache Memory) - 캐시 메모리는 CPU가 자주 사용하거나 가까운 시일 내에 사용할 가능성이 높은 데이터를 저장하는 고속 메모리이다.
- RAM - RAM은 Random Access Memory의 약자로 실행 중인 프로그램의 명령어와 데이터를 저장하는 주기억장치이다.
- ROM - ROM은 Read Only Memory의 약자로 말 그대로 읽기 전용 메모리이다.
- 플래시 메모리(Flash Memory) - 플래시 메모리는 전원이 꺼져도 데이터를 유지할 수 있는 비휘발성 메모리이다.

### 휘발성 메모리와 비휘발성 메모리

- **휘발성 메모리(Volatile Memory)**: 휘발성 메모리는 전원 공급이 중단되면 저장된 데이터가 사라지는 메모리이다. 대표적으로 레지스터, 캐시 메모리, 일반적인 RAM이 있다.
- **비휘발성 메모리(Non-Volatile Memory):** 비휘발성 메모리는 전원 공급이 중단되어도 저장된 데이터가 유지되는 메모리이다. 대표적으로 ROM과 플래시 메모리가 있다.

### 모든 RAM은 휘발성일까?

앞서 휘발성 메모리의 대표적인 예시로 '일반적인 RAM'이라고 표현했는데, 왜 그냥 RAM이라고 하지 않았을까?

그 이유는 모든 RAM이 휘발성 메모리인 것은 아니기 때문이다. RAM은 임의의 메모리 위치에 직접 접근할 수 있는 메모리를 의미하며, RAM이라는 이름 자체가 휘발성을 뜻하는 것은 아니다.

우리가 일반적으로 컴퓨터에서 사용하는 DRAM(Dynamic RAM)과 SRAM(Static RAM)은 휘발성 메모리지만 MRAM(Magnetoresistive RAM), FRAM(Ferroelectric RAM)처럼 전원이 꺼져도 데이터를 유지할 수 있는 비휘발성 RAM도 존재한다.

따라서 RAM을 무조건 휘발성 메모리라고 정의하기보다는, 일반적으로 사용되는 RAM은 휘발성이라고 생각하는게 좋다.

## 메모리 계층 구조

아니 생각을 해보니까.. 왜 굳이 레지스터, 캐시 메모리, RAM 이것저것 쓰면서 데이터를 저장하는걸까? 왜 굳이 여러개로 나눠 놓았을까? 이런 생각이 든다. 그래서 이것을 알기 위해 메모리 계층 구조를 공부해보았다.

### 메모리 계층 구조(Memory Hierarchy)란?

그래서 메모리 종류가 많은 이유가 무엇일까? 결론부터 말하면 컴퓨터의 **상충 관계** 때문이다.

**상충 관계(Trade-off)란?**

- 상충 관계는 어떤 것을 얻거나 개선하기 위해 다른 것을 포기하거나 희생해야하는 관계를 의미한다.

그럼 이런 상충 관계 개념이 메모리 계층 구조랑 무슨 상관일까?

메모리에는 대표적으로 세 가지 요소가 있다.

- Latency(지연 시간) - 데이터를 요청한 후 응답받기까지 걸리는 시간
- Capacity(용량) - 저장할 수 있는 데이터의 양
- Cost(비용) - 메모리를 구현하는 데 필요한 비용

우리 입장에서는 당연히 지연 시간은 짧고, 용량은 크고, 가격은 저렴한 메모리가 좋다. 그런데 현실에서는 이런 조건들을 모두 만족시키기가 어렵다.

### 메모리 종류별 비교


| 종류 | Latency(지연 시간) | Capacity(용량) | Cost(단위 용량당 비용) |
| ------ | -------------- | ------------ | --------------- |
| 레지스터 | 매우 짧음 | 극히 작음 | 매우 높음 |
| 캐시 메모리 | 짧음 | 작음 | 높음 |
| RAM | 상대적으로 긺 | 큼 | 중간 |
| SSD | 매우 긺 | 매우 큼 | 낮음 |
| HDD | 가장 긺 | 매우 큼 | 매우 낮음 |


위 표는 일반적인 컴퓨터의 메모리 계층을 비교한 것이다. 여기서 중요한 특징이 보인다.

상위 계층으로 갈수록 접근 속도가 빨라지지만 용량이 작고, 하위 계층으로 갈수록 접근 속도가 느리지만 용량이 커지는 경향이 있다는 것이다.



### 그럼 왜 빠른 메모리는 용량이 작을까?

대표적으로 캐시 메모리와 RAM을 비교해보자. 

**캐시 메모리(SRAM) -** CPU 캐시에는 일반적으로 SRAM이라는 메모리가 사용된다. SRAM은 데이터를 저장하기 위해 여러 개의 트랜지스터로 구성된 회로를 사용한다. SRAM은 일반적으로 DRAM보다 빠르게 데이터에 접근할 수 있지만, 저장 회로가 상대적으로 많은 공간을 차지한다. 그래서 같은 용량을 구현하려면 더 넓은 칩의 면적이 필요하고 비용도 높아진다.

**RAM(DRAM) -** 반면에 일반적인 RAM에는 DRAM이 사용되는데, 대표적인 DRAM은 SRAM보다 단순한 구조이기 때문에 같은 면적에 더 많은 데이터를 저장할 수 있다. 하지만 DRAM은 커패시터에 저장된 전하가 시간이 지나면서 감소하기 때문에 주기적으로 데이터를 재충전 해야한다. 또한 데이터에 접근하는 과정에서도 SRAM과 차이가 발생하기 때문에, 일반적으로 SRAM보다 접근 지연 시간이 길다. (커패시터(Capacitor): 전하를 저장할 수 있는 전자 부품)
