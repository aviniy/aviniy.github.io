일단 문제를 다운로드 받으면 기존 rev-basic 문제와 같이

`chall4.exe`파일 하나가 있다. 리버싱을 하기 위해 `chall4.exe`를 IDA 프로그램으로 열어보자.

그러면 아래와 같이 어셈블리어가 나오게 된다. 바로 c언어로 디컴파일해서 분석해보자.

![image.png](/images/image-48.png)



그러면 아래와 같은 c언어 코드가 나온다. 아래에 c언어 코드는 `main`함수의 코드로, 전체 실행 흐름을 보여준다.

![image.png](/images/image-44.png)

우리가 봐야할건 이 조건문이다.

```c
  if ( (unsigned int)sub_140001000(v4) )
    puts("Correct");
  else
    puts("Wrong");
```

사용자가 입력한 `v4`값을 `sub_140001000()`함수로 전달하여 `0` 이 아닌 수를 반환하면 `Correct`를 출력하고 그렇지 않으면 `Wrong`을 출력한다. 그럼 바로 `sub_140001000()`함수를 확인해보자.



아래는 `sub_140001000()`함수 코드이다.

![image.png](/images/image-45.png)

위 코드를 하나씩 이해하여보자.

```c
  for ( i = 0; (unsigned __int64)i < 0x1C; ++i ){..}
```

이 반복문은 0부터 27까지 도는 반복문이다. 왜 27일까? `0x1C`는 16진수 표현으로 28이다. C는 12를 의미하고 앞에 1은 16을 의미한다. (`16 + 12 = 28`)

파이썬으로 치면

```python
for i in range(0, 28, 1):
```

이랑 같은 의미이다.



```c
if ( ((unsigned __int8)(16 * *(_BYTE *)(a1 + i)) | ((int)*(unsigned __int8 *)(a1 + i) >> 4)) != byte_140003000[i] )
```

이 코드가 핵심이다. 코드가 복잡해보이는데.. 천천히 확인해보자.



```c
((unsigned __int8)(16 * *(_BYTE *)(a1 + i))
```

이 부분을 먼저 보면, 입력 문자열의 `i`번째 바이트를 읽어 16을 곱한 뒤, 그 결과를 부호 없는 8비트 정수형으로 변환하는 코드이다. 먼저 `a1`은 입력 문자열의 시작 주소이므로, `(a1 + i)`는 `i`번째 바이트의 주소가 된다. `(_BYTE *)`는 이 주소를 1바이트 데이터를 가리키는 포인터로 변환하고, 맨 앞의 `*`는 해당 주소에 저장된 값을 읽는다. 이렇게 읽은 값에 16을 곱하면 비트가 왼쪽으로 4칸 이동한다. 이후 `(unsigned __int8)`로 변환하면서 하위 8비트만 남긴다. 예를 들어 읽은 값이 `0x42`라면, 16을 곱해 `0x420`이 되고 최종적으로 `0x20`이 남는다.

그 다음 아래 코드를 이해하면 된다.

```c
((int)*(unsigned __int8 *)(a1 + i) >> 4))
```

이 부분은 입력 문자열의 `i`번째 바이트를 읽어 오른쪽으로 4비트 이동하는 코드이다. 먼저 `(a1 + i)`로 읽을 바이트의 주소를 구하고, `(unsigned __int8 *)`로 해당 주소를 부호 없는 8비트 정수를 가리키는 포인터로 변환한다. 이어서 맨 앞의 `*`로 그 주소에 저장된 값을 읽고, `(int)`로 값의 변화 없이 `int`형으로 변환한다. 그리고 오른쪽 비트 시프트 연산자 `>>`로 값을 4비트 이동한다. 이 오른쪽 비트 시프트 연산자는 파이썬에서도 사용된다. 예를 들어 읽은 값이 `0x42`라면, `0x42 >> 4`의 결과는 `0x04`이다.

그렇게 나온 두 값을 `|` 으로 OR연산을 해주고 `!= byte_140003000[i]`로 `byte_140003000`에 있는 데이터에서 `i`번째씩 뽑아 비교하고 다르다면 0을 반환하고 모두 같다면 1을 반환하는 식이다. 즉, 사용자가 플래그를 대입하면 1이 반환하여 `Correct`가 뜨는 원리이다. 우리가 위에서 본 조건문이랑 연계해서 생각하면 된다.

## 요약

사실 위의 복잡한 코드는 한 바이트의 상위 4비트와 하위 4비트를 서로 바꾸는 니블 스왑(Nibble Swap)을 구현한 것이다. (니블 스왑 하나 하려고 여기까지 어그로 끌은것이다.)

### 니블 스왑이란?

니블 스왑을 이해하기 전에 니블이 뭔지 알면 좋을거 같다. **니블(Nibble)**은 4비트를 묶어 부르는 단위이다. 예를 들어 `A`라는 문자가 하나 있다 쳐보자. `A`의 아스키 코드는 65로, 이진수로 표현하면 `0100 0001`이다. 이렇게 4비트씩 묶는게 니블이고, 니블 스왑은 상위 4비트와 하위4비트의 위치를 바꾸는 것이다. 즉 `0100 0001`이 `0001 0100`이 되는것이다. 65에서 20이 되는것이다. `A`가 `DC4` 된다. 근데 `DC4`같은 경우 출력 가능한 일반 문자가 아니기에 값을 확인하려면 16진수로 출력하면 되고, IDA에서도 바이트 데이터를 이러한 16진수 형태로 보여준다.

### 풀이 방향 (어떻게 디코딩을 해야할까?)

기존 `byte_140003000`에는 정답의 각 바이트에 니블 스왑을 적용한 값이 저장되어 있다. 따라서 이 배열의 값에 니블 스왑을 한번 더 적용하면 원래 입력을 복원할 수 있을것이다. 상위 4비트와 하위 4비트의 위치를 두 번 바꾸면 원래대로 돌아오기 때문이다. 

예시: `0100 0001` -> `0001 0100` -> `0100 0001`

## 디코딩 코드

```python
data = [
    0x24, 0x27, 0x13, 0xC6, 0xC6, 0x13, 0x16, 0xE6, 0x47, 0xF5,
    0x26, 0x96, 0x47, 0xF5, 0x46, 0x27, 0x13, 0x26, 0x26, 0xC6,
    0x56, 0xF5, 0xC3, 0xC3, 0xF5, 0xE3, 0xE3,
    0x00, 0x00, 0x00, 0x00, 0x00
]

decoded = []

for i in range(28):
    decoded.append(((data[i] << 4) & 0xFF) | (data[i] >> 4))

print(bytes(decoded).rstrip(b"\x00").decode())
```

위처럼 `byte_140003000`의 데이터들을 가져와 `data`리스트를 만들어 주고 플래그 바이트를 담을 `decoded`리스트를 만들어준다. 반복문에서는 각 바이트의 상위 4비트와 하위 4비트를 교환해 `decoded`리스트에 추가한다. 마지막으로 바이트 데이터를 만들고, 끝의 널문자를 제거한 후 출력한다.
