격리된 VirtualBox Windows 10 실험 VM에서 Petya 계열 샘플의 부팅 전 동작과 복구 가능 범위를 분석했다. Windows Defender 탐지명은 `Ransom:DOS/Petya.A`였고, 부트 영역에서도 Petya 문구를 확인했다.

## 실험 범위와 보존

감염 후 VM의 네트워크 연결을 끊고, 복구 작업 전 감염 상태의 가상 디스크를 별도로 복제했다. 분석은 이 실험 VM과 복제본을 대상으로 수행했다. 실행 파일이나 감염 디스크 이미지는 이 글에 배포하지 않는다.

## 부팅 증상

재부팅 후 Windows 로그인 화면 대신 부팅 전 키 입력 화면과 Petya 안내 문구가 나타났다. 이 상태에서는 Windows가 정상적으로 시작되지 않았다. 부트 영역 문자열과 Defender 탐지명이 서로 일치해 Petya.A 계열 부트로커로 판단했다.

## 복구 시도에서 확인한 점

Windows 복구 콘솔에서 MBR을 복구하자 잠금 화면은 제거됐지만 정상 부팅으로 이어지지는 않았다. 디스크를 직접 분석하니 NTFS/MFT의 중요한 메타데이터도 손상돼 있었다. 따라서 부트로더만 되돌려서는 원래 파일 시스템 상태를 복원할 수 없었다.

일부 파일은 추출할 수 있었다. 작은 파일 중 MFT 레코드에 데이터가 남아 있던 것은 원문 복구가 가능했지만, `.crazy` 확장자가 붙은 파일은 추출해도 암호화된 데이터였으며 원문 복호화에는 실패했다.

| 항목 | 결과 |
| --- | --- |
| Petya 잠금 화면 제거 | 성공 |
| Windows 정상 부팅 복구 | 실패 |
| NTFS 전체 복구 | 실패 |
| 일부 파일 단위 복구 | 성공 |
| 암호화된 파일의 원문 복호화 | 실패 |

## 정적 분석 메모

별도 정적 분석에서는 샘플을 실행하지 않고 디스크 복제본에서 파일 바이트를 읽었다. 관리자 권한 요구 manifest와 디스크 접근에 쓰일 수 있는 API 호출 흔적이 확인됐다. 이런 단서는 부트 단계 조작 가능성과 부합하지만, 정적 분석만으로 각 API의 실제 실행 경로를 모두 확정할 수는 없다.

이번 실험의 핵심은 **MBR 복구 성공과 파일 시스템 복구 성공은 별개**라는 점이다. 재현 실험이라면 실행 전 깨끗한 스냅샷과 격리된 네트워크, 복구 전 디스크 복제본이 필요하다.
